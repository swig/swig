42.1 Introduction

The experimental MATLAB module generates a MEX gateway and MATLAB proxy files for C and C++ declarations. Functions are placed in a MATLAB package and C++ classes become MATLAB handle classes. The generated files also target the Octave MEX interface; the existing Octave module uses Octave's native C++ interface instead.

This module has experimental status. Applications should test the generated wrappers with their chosen MATLAB or Octave release. MATLAB requires a working MEX compiler, configured with mex -setup or mex -setup C++.

42.2 Getting started

Create an interface named matlab_example.i:

%module matlab_example
%inline %{
int add(int a, int b) {
  return a + b;
}
class Counter {
public:
  Counter(int initial = 0) : value(initial) {}
  int increment() { return ++value; }
  int value;
};
%}

Generate the wrappers:

swig -c++ -matlab matlab_example.i

SWIG writes matlab_example_wrap.cxx, a +matlab_example package directory, and shared support files such as SwigRef.m and SwigMem.m. Keep the support files alongside the package directory. Compile and use the module from MATLAB: 

mex -output matlab_exampleMEX matlab_example_wrap.cxx
assert(matlab_example.add(2, 3) == 5);
counter = matlab_example.Counter(10);
assert(counter.increment() == 11);
assert(counter.value() == 11);
counter.value(20);
assert(counter.increment() == 21);
delete(counter);

Add the directory containing +matlab_example and the MEX file to the MATLAB path, rather than adding +matlab_example itself. Use -matlab without -c++ for C interfaces, then compile the generated C file with mex.

42.3 Module and command line options

  • -pkgname name selects the MATLAB package name. The default is the SWIG module name.
  • -mexname name selects the gateway function name. The default is the module name followed by MEX. Compile with the same mex -output name.
  • -opprefix prefix selects the prefix for global C++ operator wrappers. The default is op_.
  • -nodelete generates do_delete instead of automatic delete methods. Applications must explicitly release owned native objects.

-outdir selects the directory for MATLAB files. Use %rename for declarations whose names cannot be MATLAB identifiers. MATLAB keywords are renamed with a trailing 1.

42.4 Types and ownership

Scalar real numeric inputs map to C and C++ arithmetic parameters. Integer parameters reject fractional, complex, nonfinite, and out of range values. Boolean parameters accept logical scalars. Integer outputs use MATLAB integer classes; floating point outputs use MATLAB doubles.

With C++11 or later, enum inputs are checked against the range of their C++ underlying type. Signed enum outputs use MATLAB int64, and unsigned enum outputs use uint64, preserving all 64 bits. These conversions also apply to constants and container elements. C and C++98 wrappers retain the ordinary int enum conversion.

Character row vectors map to char * and, with %include <std_string.i>, to std::string. The narrow string mapping preserves bytes, including embedded zero bytes in std::string; characters outside the byte range are rejected. This mapping does not perform UTF-8 encoding. MATLAB's string objects require an explicit conversion to a character vector. With %include <std_wstring.i>, wide strings map to MATLAB UTF-16 code units; native wide characters above 65535 are rejected. Octave uses byte characters instead, so this mapping preserves its UTF-8 bytes and rejects native wide characters above 255.

Include the corresponding standard library interface and instantiate a %template before declarations using a container. Vectors accept row or column cell arrays and return row cell arrays. Empty cell arrays represent empty containers. Wrapped std::map values remain proxy objects rather than converting to MATLAB maps. For example: 

%include <std_vector.i>
%template(DoubleVector) std::vector<double>;
std::vector<double> scale(const std::vector<double> &values);

result = matlab_example.scale({1, 2, 3});

Wrapped classes derive from SwigRef. Objects created by constructors are owned by their MATLAB proxies and are destroyed when the proxy is deleted. The %newobject directive marks factory results as owned. Borrowed pointer results do not transfer ownership. Use [] for a null pointer input. Do not modify the internal swigPtr property or retain borrowed objects after their native owners have been destroyed.

Members use method syntax: obj.member() reads a member and obj.member(value) writes it. Global variables and constants use package functions. Static members and class constants use static methods. C++ operators map to MATLAB methods such as plus, minus, mtimes, eq, and lt.

42.5 Virtual callbacks

Enable %module(directors="1") and %feature("director") ClassName; to override C++ virtual methods in a MATLAB subclass. The subclass constructor must call the generated superclass constructor. The matlab_director regression demonstrates virtual dispatch and a custom directorargout typemap for multiple MATLAB outputs. Director support is experimental, including ownership of callback objects. Director subclasses are retained in persistent MATLAB storage so that native calls can reach them. Call delete(callback) explicitly when a MATLAB owned director is no longer needed; clearing the last workspace variable alone does not release this retained reference. Native destruction removes the stored reference. Invalid callback return values and callback errors are translated to MATLAB errors at the MEX gateway after native stack cleanup.

42.6 Customizing generated code

%exception can translate C++ exceptions using SWIG_exception. Uncaught C++ exceptions must not escape a MEX gateway. %feature("autodoc", "1") adds usage information to generated help text, and %feature("docstring") supplies explicit help text.

Within a class, %matlabcode inserts instance methods, %matlabcode_static inserts static methods, and %matlabcode_class inserts class level declarations. %feature("matlabprepend") and %feature("matlabappend") insert code before and after a proxy method's MEX call.

42.7 Building and testing SWIG

MATLAB is optional when building the SWIG executable. Configure the regression suite with the MATLAB installation directory: 

./configure --with-matlab=/path/to/MATLAB
make
make check-matlab-test-suite
cd Examples/test-suite/matlab
make matlab_features.cpptest

The suite generates wrappers, compiles each MEX file, and runs an accompanying _runme.m script when present. Runtime failures propagate to make. To exercise the MEX backend with Octave, configure with --enable-octave-for-matlab --with-matlab=/path/to/octave; an associated mkoctfile compiler is required. MATLAB and Octave have different class and exception behavior, so testing on one does not replace testing on the other.
