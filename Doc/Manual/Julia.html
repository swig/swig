43.1 Introduction

The experimental -julia target generates a C++ wrapper with a C calling interface and a Julia module that calls it using ccall. It requires a C++11 compiler and Julia development headers. The initial runtime tests run on Julia 1.6.2 and 1.13.0; Julia 1.12.6 has also been validated locally. Build the wrapper against the Julia installation that will load it; compatibility of a compiled wrapper across Julia versions is not promised.

43.2 Building a module

For example, save this interface as example.i:

%module example
%inline %{
class Counter {
public:
  Counter(int value = 0) : value_(value) {}
  int increment(int amount = 1) { return value_ += amount; }
private:
  int value_;
};
%}

Generate the wrapper with swig -c++ -julia example.i. This writes example_wrap.cxx and example.jl. Build a shared library named libexample_wrap, with the platform's shared library extension, in the same directory as example.jl. A typical Linux build, where JULIA_HOME is the Julia installation prefix, is: 

swig -c++ -julia example.i
c++ -std=c++11 -fPIC -shared -I"$JULIA_HOME/include/julia" \
    example_wrap.cxx -L"$JULIA_HOME/lib" -ljulia -o libexample_wrap.so

Load and use the generated module:

include("example.jl")
using .example
counter = Counter(10)
counter.increment()      # 11
counter.increment(4)     # 15

The generated file obtains its library extension from Libdl.dlext. The C++ runtime used by the wrapper must be compatible with the runtime loaded by Julia. In particular, an older Julia distribution may bundle an older C++ runtime than the compiler used to build the wrapper.

To configure SWIG's Julia examples and tests, use ./configure --with-julia=/path/to/julia, then make check-julia-test-suite. The executable's installation must contain include/julia/julia.h and lib/libjulia. An example is provided in Examples/julia/simple.

43.3 Generated interface

Functions become Julia functions. C++ overloads use Julia dispatch; overloads whose signatures would be ambiguous are combined using conversion probes. Default arguments produce methods for the corresponding argument counts. Instance methods support both example.increment(counter, 4) and counter.increment(4). Static methods support ClassName.method(arguments...).

Public member variables have accessors named ClassName_member_get and ClassName_member_set. These are functions in the generated module, not Julia struct fields. Global variables similarly have name_get and name_set accessors. Use %rename for names that conflict with Julia keywords, Base, Core, or names used by the generated runtime. Julia names are case sensitive.

Integer arguments accept Julia integers and use the corresponding C ABI width. Out-of-range arguments fail Julia's conversion to that ABI type. Floating point arguments accept Real; Boolean arguments accept Bool. std::string arguments and results use Julia String, preserving embedded zero bytes. C string arguments use Cstring conversion and must not contain embedded zero bytes. Primitive pointers use Julia Ptr values and do not acquire a finalizer.

Named enums use Julia enum types with the signedness and integer width selected by the C++ compiler. Enum values, including aliases and compound expressions, are evaluated in C++ rather than parsed as integer literals by SWIG. Scoped enum constants retain their Julia enum type; unscoped bare constants are integers. Integer arguments must fit the enum's underlying type. Enum return values preserve that type's full range.

std_vector.i, std_pair.i, and std_string.i supply initial STL support. Vectors of double, long long, and std::string can be copied to and from native Julia vectors. Double vectors accept Vector{Float64} and Vector{Int64}; integer vectors accept Vector{Int64}; string vectors accept Vector{String}. Pair results can become Julia tuples; unsigned integer elements use UInt64 so values above the signed integer range are preserved. These are copies; modifying a returned Julia array does not modify the C++ container. std_map.i only supplies declarations for interfaces that provide their own map conversion typemaps.

43.4 Ownership and inheritance

Class proxies contain a pointer to a C++ object. Constructor results and class values returned by value are owned and deleted by Julia finalizers. Pointer and reference results are borrowed unless the function has %newobject. Borrowed results retain their argument proxies so a method's receiver remains alive while a returned subobject is in use. A null class pointer result becomes nothing. Calling a method on a finalized proxy raises an error. Do not explicitly finalize an owner while borrowed references are still in use.

Julia structs do not reproduce C++ inheritance. The generator forwards inherited methods and accepts derived proxies in base-class arguments. Conversions use SWIG's type table, including pointer adjustment for multiple inheritance. Types are currently registered separately for each generated module; importing wrapped classes from another module is not supported.

43.5 Exceptions and directors

C++ exceptions are caught inside the wrapper. The Julia side raises the module's SwigError; std::exception::what() is retained. Other C++ exceptions receive a generic message. Error state is local to the calling thread and cleared by the next wrapper call.

Initial director support is available with %module(directors="1") and %feature("director") ClassName. For a class with a public default constructor, ClassName(julia_object) constructs a director whose virtual methods call Julia methods named ClassName_method. Define an overload of this function for the type of julia_object. Missing overrides call the C++ implementation, or raise an error for a pure virtual function. Director objects retain their Julia callback object until destroyed. Callback code must run on a thread already supported by the Julia runtime.

The initial director typemaps cover scalar and string arguments and returns. Integer overrides return Int64, floating point overrides return Float64, and Boolean overrides return Bool. An exception, a wrong return type, or an integer return value outside the native type's range becomes SwigError. Integer callback arguments use Int64; unsigned native arguments larger than typemax(Int64) are rejected. Parameterized director constructors and general container director typemaps are not implemented.

43.6 Typemaps and limitations

The ctype, in, out, freearg, and typecheck typemaps describe the C wrapper boundary. jltype supplies the Julia ccall type, jlparam supplies the public argument annotation, and jlout supplies the result expression; $call in jlout is replaced by the generated call. The out attribute on ctype and jltype can specify a separate result type. Hidden numinputs=0 arguments with argout typemaps can return multiple results from a C++ void function. %insert("julia") inserts code into the generated Julia module.

This is an experimental target with a selected initial test suite, not the full SWIG language test suite. Nested classes, cross-module imports, general operator mapping, complete STL support, arbitrary pointer/reference combinations, and arbitrary multi-argument typemaps are not supported. Unsupported callable types produce a SWIG warning. The initial runtime validation is on Linux; other platforms have not yet received equivalent validation.
